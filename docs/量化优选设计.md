# 量化优选功能设计

> 文档状态：评审修订版
>
> 版本：v1.3
>
> 日期：2026-07-26
>
> 适用仓库：Longbridge Quant Console

v1.3 延续 v1.2 的统一候选口径：取消普通股/ETF 子类型、ETF 敞口方向和杠杆倍数的数据门禁，并移除严格 NBBO 硬过滤与评分。候选范围以 Longbridge `usmain` 的点时目录召回为准；流动性统一由未复权日成交额衡量。本版进一步按 Longbridge 官方接口文档冻结自动采集方案和调用边界，明确批量报价与静态信息可直接获取，但全市场历史 K 线仍受单标的调用方式和账户月度唯一标的额度约束。

## 1. 设计结论

新增独立菜单 **“量化优选”**，用于从 Longbridge 美国主板证券目录中筛选适合未来 5～20 个交易日量化交易的候选。页面不要求用户维护 LONG/SHORT 两个池，也不提供证券类型或 ETF 敞口方向选择；每次运行只产生一份统一的候选榜单。

首版采用“硬过滤 → 量化评分 → AI 最终确认 → 排名输出”的四段式流程：

```text
美股证券目录
  → 市场、交易状态与数据质量硬过滤
  → 量化评分 Q（0～100）
  → Q ≥ 65 的 Top 30 进入 AI
  → AI 评分 A（0～100）并作出 SELECT / REJECT
  → 最终分 F = 70% × Q + 30% × A
  → 同时满足全部入选门槛后，输出 Top 10
```

AI 不是说明文字生成器，也不是可有可无的加分项。标的必须得到 AI 的 `SELECT` 决策才能进入最终榜单；AI 不可用、输出无效或认为风险过高时，该标的不得作为最终入选结果。量化硬过滤仍拥有最高优先级，AI 不得推翻市场、交易状态、流动性和数据质量等确定性规则。

## 2. 需求口径

### 2.1 统一证券范围

首版按以下统一口径处理：

- 只处理 `market=US`，候选必须来自 Longbridge `board=usmain` 的点时证券目录，并在 NYSE、NASDAQ 或 NYSE American 上市；
- 不区分普通股、权益 ETF、债券 ETF、商品 ETF、正向/反向 ETF 或杠杆倍数，所有召回标的进入同一个候选池，使用完全相同的硬过滤、量化指标、权重、AI 门槛和最终排名；
- 页面不提供证券类型或方向筛选器，不分组展示，也不为任何类型预留名额；
- 反向/做空 ETF 的入选含义仍是买入该证券本身，不生成卖空或底层资产订单；
- `usmain` 不是严格的普通股/ETF 分类。取消产品元数据后，候选可能包含 ADR、REIT、优先股、封闭式基金、权证或 Units 等目录内证券；首版接受这一范围，不通过名称正则或 AI 猜测类别；
- 期权使用独立证券目录，不纳入 `usmain` 召回；
- OTC 和交易状态异常的标的继续排除。

现有证券目录的 `board=usmain` 语义是“美国主板挂牌证券，可能包含基金”，因此它只定义召回边界，不声称能证明产品类别。运行只保存目录来源、目录版本、代码、名称、市场、交易所和捕获时间；`asset_class`、`exposure_direction`、`leverage` 不再是输入契约。将来若接入这些字段，只能作为可选展示或下单前风险提示，缺失不得使运行变为 `partial` 或 `failed`。

### 2.2 目标

- 将复杂的智能选股流程压缩为一次点击即可完成的固定流程；
- 给出最多 10 只流动性好、趋势明确、相对强势、风险适中的美国主板证券；
- AI 读取量化指标、K 线、市场环境、新闻和事件信息后，直接决定是否入选；
- 所有输入、规则版本、AI 请求与输出可回放、可审计；
- 结果可供人工观察或后续策略引用，但首版不自动下单。

### 2.3 非目标

- 不替代现有“智能选股”及其多空观察池、Screener 和回测管理能力；
- 不做日内高频、直接卖空、期权或加密资产筛选；
- 不让用户在首版自由修改几十项因子和权重；
- 不承诺榜单中的股票一定盈利，也不把历史相关性描述为因果收益；
- 不直接连接真实下单接口。

### 3.2 页面结构

页面默认展示最近一次完整运行结果：

1. 顶部操作栏：数据截止时间、规则版本、AI 模型、`开始筛选`、`刷新状态`；
2. 运行摘要：证券总数、硬过滤后数量、量化候选数、AI 完成数、最终入选数；
3. 最终榜单：排名、代码/名称、最终分、量化分、AI 分、AI 信心度、趋势、相对强度、流动性、风险、数据时间；

## 4. 候选范围与硬过滤

硬过滤不计分，任一规则失败即排除。首版固定如下：

| 编号 | 硬过滤规则 | 首版阈值 | 缺失数据处理 | 目的 |
| --- | --- | ---: | --- | --- |
| H1 | 市场与目录 | `market=US` 且来自点时 `usmain` 目录 | 排除 | 限定 Longbridge 美国主板召回范围 |
| H2 | 交易所 | NYSE / NASDAQ / NYSE American | 排除 | 排除 OTC 等市场 |
| H3 | 交易状态 | `normal` | 排除 | 排除停牌、退市、待上市等状态 |
| H4 | 最新价 | `≥ 5 USD` | 排除 | 规避低价证券和异常撮合 |
| H5 | 20 日中位日成交额 | `≥ 10 million USD` | 排除 | 保证基本成交容量并控制交易成本代理 |
| H6 | 日 K 数据 | 最近 90 个交易日至少 85 根有效 K 线 | 排除 | 保证指标可计算且数据连续 |
| H7 | 数据时效 | 候选与 SPY 的 K 线均归属 `data_as_of`，目录和交易状态在本次运行冻结 | 排除 | 禁止混用不同截止日或可变目录数据 |
| H8 | 基准排除 | 标准化代码不在基准集合中；首版集合为 `{SPY}` | 排除 | 防止基准进入候选榜单 |

补充规则：

- 前复权 OHLC 用于收益、均线、MACD、ATR、波动和回撤；流动性使用未复权成交量和未复权成交额，禁止用复权历史价格乘以未复权成交量；数据源有原始成交额时直接使用，否则以同一根未复权 K 线的 `raw_close × raw_volume` 计算；
- 目录证据需保存来源、`board`、获取时间、目录版本及原始载荷哈希；目录内产品类别未知不构成数据缺失；
- 市值和资产管理规模不是统一口径，因此不作门槛也不参与评分；容量与交易成本只使用 20 日中位日成交额作为统一代理；
- SPY 只作为相对强度基准，不是候选标的；H8 失败时保存排除原因 `benchmark_symbol`。

所有收益、趋势、动量、波动和回撤指标均按候选标的自身价格序列计算。不根据名称或模型知识对反向产品取反，也不切换到 SHORT 评分；任何证券自身价格上涨、相对 SPY 走强时，都按同一公式获得对应分数。

### 4.1 盘口数据边界

`data_as_of` 固定为最近一个已完整结束的 NYSE 交易日，正常交易日和提前收市日仍由交易所日历证明。首版不要求指定历史时点的 SIP NBBO，不调用逐证券 `depth` 来决定候选资格或 Q 分，也不因为盘口缺失把运行标记为 `partial`。

Longbridge `depth` 是单标的当前可见盘口，不能在本设计中宣称为跨交易场所汇总的 NBBO，也不能可靠补录历史收盘盘口。它可以在页面查看详情时按需展示为“当前可见价差”，但必须同时显示获取时间和来源；该辅助值不进入运行快照、输入哈希、缓存身份、Q/A/F 或历史效果评估。

未来接入自动下单时，应在执行层使用订单到达时的实时双边报价做独立风控，例如价差超过 30 bps 时暂缓交易。执行前检查反映实际成交条件，不得回写或改变已经发布的历史选股结果。

## 5. 评分模型

### 5.1 总体比例

量化分 `Q` 和 AI 分 `A` 均归一化到 0～100：

```text
Q = 20% × 流动性
  + 30% × 趋势
  + 20% × 相对强度
  + 15% × 动量确认
  + 15% × 风险适配

A = 60% × AI 适合度
  + 40% × AI 信心度 × 100

F = 70% × Q + 30% × A
```

AI 适合度和 AI 信心度来自同一个模型，二者不是统计上独立的因子；这里的 60/40 是用于约束模型输出的治理比例，不能当作两项独立收益来源。AI 是否真正改善排序必须按第 9.2 节与纯量化榜单做配对评估。

最终分的实际贡献如下：

| 项目 | 占最终分比例 |
| --- | ---: |
| 流动性 | 14.0% |
| 趋势 | 21.0% |
| 相对强度 | 14.0% |
| 动量确认 | 10.5% |
| 风险适配 | 10.5% |
| AI 适合度 | 18.0% |
| AI 信心度 | 12.0% |
| **合计** | **100.0%** |

比例和下述算法固定在 `quant-selector-score-v1.2` 中。配置或算法变更必须升级评分版本，历史结果不得按新规则重写。

### 5.2 流动性，量化分占比 20%

```text
流动性分 = 20 日中位日成交额得分
```

| 20 日中位日成交额 | 得分 |
| --- | ---: |
| `≥ 100M USD` | 100 |
| `50M～<100M` | 85 |
| `20M～<50M` | 70 |
| `10M～<20M` | 50 |
| `<10M` | 硬过滤失败 |

成交额同时承担容量和交易成本代理职责。它不能精确预测实际价差，因此页面和文档不得把流动性分解释为已验证的成交价格；真实下单必须另做执行前检查。

### 5.3 趋势，量化分占比 30%

```text
趋势分 = 60% × 均线结构得分 + 40% × MA20 十日斜率得分
MA20 十日斜率 = MA20(t) / MA20(t-10) - 1
```

| 均线结构 | 得分 |
| --- | ---: |
| `Close > MA20 > MA60` | 100 |
| `Close > MA20` 且 `MA20 ≤ MA60` | 70 |
| `Close ≤ MA20` 且 `MA20 > MA60` | 40 |
| `Close ≤ MA20 ≤ MA60` | 0 |

| MA20 十日斜率 | 得分 |
| --- | ---: |
| `≥4%` | 100 |
| `2%～<4%` | 80 |
| `0%～<2%` | 60 |
| `-2%～<0%` | 30 |
| `<-2%` | 0 |

### 5.4 相对强度，量化分占比 20%

```text
相对强度分 = 60% × RS20 得分 + 40% × RS60 得分
RSn = 股票 n 日收益率 - SPY 同期收益率
```

| RS20 | 得分 |
| --- | ---: |
| `≥10 个百分点` | 100 |
| `5～<10` | 85 |
| `0～<5` | 65 |
| `-5～<0` | 35 |
| `<-5` | 0 |

| RS60 | 得分 |
| --- | ---: |
| `≥15 个百分点` | 100 |
| `7～<15` | 85 |
| `0～<7` | 65 |
| `-7～<0` | 35 |
| `<-7` | 0 |

### 5.5 动量确认，量化分占比 15%

```text
动量确认分 = 40% × RSI14 得分
            + 40% × MACD 柱状态得分
            + 20% × 量价确认得分
```

| RSI14 | 得分 |
| --- | ---: |
| `50～65` | 100 |
| `40～<50` | 70 |
| `>65～70` | 60 |
| `30～<40` | 35 |
| `>70～75` | 25 |
| `<30` 或 `>75` | 0 |

| MACD 柱状态 | 得分 |
| --- | ---: |
| 大于 0 且连续两日上升 | 100 |
| 大于 0 但回落 | 70 |
| 小于等于 0 但连续两日上升 | 40 |
| 小于等于 0 且未上升 | 0 |

量价确认使用 `5 日收益率` 和 `5 日平均成交量 / 20 日平均成交量`：

| 量价状态 | 得分 |
| --- | ---: |
| 5 日收益为正且量比 `≥1.2` | 100 |
| 5 日收益为正且量比 `0.8～<1.2` | 70 |
| 5 日收益为正且量比 `<0.8` | 40 |
| 5 日收益小于等于 0 | 0 |

### 5.6 风险适配，量化分占比 15%

该维度不是“波动越低越好”，而是寻找仍有交易空间、但不过度失控的区间。

```text
风险适配分 = 40% × ATR14/Close 得分
            + 30% × 20 日年化波动率得分
            + 30% × 60 日最大回撤得分
```

| ATR14 / Close | 得分 |
| --- | ---: |
| `1.5%～4%` | 100 |
| `1%～<1.5%` | 70 |
| `>4%～6%` | 60 |
| `<1%` | 40 |
| `>6%～8%` | 30 |
| `>8%` | 0 |

| 20 日年化波动率 | 得分 |
| --- | ---: |
| `20%～50%` | 100 |
| `15%～<20%` 或 `>50%～60%` | 70 |
| `10%～<15%` 或 `>60%～70%` | 40 |
| `<10%` 或 `>70%` | 0 |

| 60 日最大回撤绝对值 | 得分 |
| --- | ---: |
| `≤10%` | 100 |
| `>10%～20%` | 70 |
| `>20%～30%` | 30 |
| `>30%` | 0 |

### 5.7 指标精确复算口径

所有指标使用按 NYSE 交易日升序排列的数据，以当前 `data_as_of` K 线为窗口右端点。计算使用 IEEE 754 `float64`，中间过程不舍入，分档和门槛均比较未舍入值；数据库保存 Q、A、F 及分项到小数点后 6 位，页面只显示 1 位小数。不得用页面显示值反推排名。标准化证券代码使用大写并去除首尾空白。

价格指标使用同一快照中的前复权 OHLC，量与成交额指标使用未复权数据，具体定义如下：

- `SMAn(t)`：包含 t 日在内的最近 n 个有效前复权收盘价的算术平均；`MA20 十日斜率 = MA20(t) / MA20(t-10) - 1`，因此必须同时存在两个完整 MA20 窗口；
- `RSn`：先将标的与 SPY 对齐到共同的 NYSE 交易日，再计算 `C(t) / C(t-n) - 1`，两者相减；n 日收益需要 n+1 个共同收盘价，不允许以前值填充缺失交易日；
- `RSI14`：令 `gain=max(ΔC, 0)`、`loss=max(-ΔC, 0)`，前 14 个价格变化的 gain/loss 算术平均作为 Wilder 初值，之后按 `(前值 × 13 + 当日值) / 14` 平滑；平均 gain 和 loss 同为 0 时 RSI=50，仅平均 loss 为 0 时 RSI=100，否则 `RSI=100-100/(1+avg_gain/avg_loss)`；
- `MACD(12,26,9)`：EMA 的 `α=2/(N+1)`，每条 EMA 以最早 N 个有效观测的 SMA 为初值；`DIF=EMA12-EMA26`，Signal 以最早 9 个有效 DIF 的 SMA 为初值，Histogram=`DIF-Signal`；“连续两日上升”严格指 `hist(t) > hist(t-1) > hist(t-2)`；
- `ATR14`：`TR(t)=max(high-low, abs(high-prev_close), abs(low-prev_close))`，第一根因没有前收盘而不产生 TR；以前 14 个有效 TR 的算术平均为 Wilder 初值，之后按 `(前 ATR × 13 + 当日 TR) / 14` 平滑；`ATR14/Close` 的分母为当日前复权收盘价；
- `20 日年化波动率`：最近 21 个前复权收盘价产生 20 个简单收益 `C(t)/C(t-1)-1`，使用样本标准差 `ddof=1` 并乘以 `sqrt(252)`；
- `60 日最大回撤绝对值`：在包含 t 日的最近 60 个前复权收盘价中，计算所有 `i≤j` 的 `C(j)/C(i)-1`，取最小值的绝对值；同日端点允许产生 0；
- `5 日收益率` 使用最近 6 个前复权收盘价；5 日和 20 日平均成交量均为对应窗口未复权成交量的算术平均；20 日中位日成交额为对应窗口未复权成交额的中位数，偶数样本取中间两个值的算术平均。

窗口内出现非有限值、非正价格、负成交量、重复交易日、所需样本不足，或标的与 SPY 无法按上述规则对齐时，相应关键指标视为缺失。关键指标缺失的标的必须以具体原因排除，不能补零、前向填充或给中性分。实现需为每个公式、阈值边界、缺失分支和排序并列场景提供固定输入测试向量。

### 5.8 AI 候选与最终入选门槛

AI 候选集合只来自 H1～H8 全部通过且 `Q ≥ 65` 的标的，稳定排序键固定为：

1. 未舍入 Q 降序；
2. 未舍入的 20 日中位日成交额降序；
3. 标准化证券代码升序。

取该顺序前 30 只，不扩大第 30 名并列集合。候选选择清单必须包含所有初始候选的硬过滤结果、最终 Q、稳定排序键和最终 Top 30，并进入输入哈希；任何实现不得把硬过滤失败或 `Q < 65` 的标的补入 30 只。由于 Q 不再依赖二次盘口查询，冻结输入计算完成后即可直接确定精确集合，不需要上界剪枝或外部边界证明。

标的进入最终 Top 10 必须同时满足：

1. H1～H8 全部通过；
2. 量化分 `Q ≥ 65`；
3. AI 决策为 `SELECT`；
4. AI `confidence ≥ 0.70`；
5. AI `suitability_score ≥ 70`；
6. AI `risk_level` 不为 `HIGH`；
7. 最终分 `F ≥ 72`；
8. 所有评分输入通过完整性和哈希校验。

先按未舍入 `F`、`Q`、AI 信心度、20 日中位日成交额依次降序，最后按标准化证券代码升序稳定排序，直接取最多 10 只。首版不设置证券类型或方向配额，也不使用只适用于普通股的 GICS 行业限额。若只有 4 只合格，则只返回 4 只，不降低门槛凑满数量。

## 6. AI 直接决策

### 6.1 AI 输入

只把第 5.8 节确定的 `Q ≥ 65` 稳定排序 Top 30 发送给 AI。每只标的输入：

- 证券代码、名称、交易所、`usmain` 目录来源及证据版本；不提供或推测产品类别、ETF 敞口方向和杠杆倍数；
- 数据截止时间、量化总分及完整分项；
- 最近 90 根日 K 和计算后的 MA、RS、RSI、MACD、ATR、波动率、回撤及成交额；
- SPY 的同期市场状态；
- 最近 7 天最多 10 条去重新闻的标题、来源、发布时间和摘要；
- 已知财报日、拆股、分红及其他适用事件；不适用于某类产品的字段标记为 `not_applicable`，不得伪装成缺失；
- 所有缺失字段和外部数据状态。

新闻和摘要属于不可信数据，只能作为事实材料，不得改变系统指令或输出格式。AI 不得补造缺失价格、事件日期或新闻。

提示词必须明确：模型只按输入中可验证的价格、量、新闻和事件判断该证券自身是否适合持有，不得根据代码或名称自行补造产品类别、方向或杠杆倍数。输入没有产品结构事实时，AI 可以基于已观测波动和回撤判断风险，但不得声称已经评估杠杆衰减或底层敞口。

### 6.2 AI 输出契约

提示词版本为 `quant-selector-ai-prompt-v2`，温度固定为 `0.1`。模型必须返回结构化 JSON：

```json
{
  "decision": "SELECT",
  "confidence": 0.82,
  "suitability_score": 84,
  "risk_level": "MEDIUM",
  "time_horizon_days": 10,
  "reasons": ["趋势与相对强度同时为正", "量价配合稳定"],
  "risks": ["五个交易日后公布财报"],
  "entry_condition": "价格保持在 MA20 上方且成交量不低于 20 日均量的 0.8 倍",
  "invalidation_condition": "收盘跌破 MA20 或相对 SPY 的 20 日强度转负",
  "data_conflicts": []
}
```

约束如下：

- `decision` 只能是 `SELECT`、`REJECT` 或 `INSUFFICIENT_DATA`；
- `confidence` 范围为 0～1，`suitability_score` 范围为 0～100；
- `SELECT` 必须给出至少 2 条理由、1 条风险、可机器复核的入场和失效条件；
- 新闻或事件与行情截止日冲突时必须列入 `data_conflicts`；
- 不请求或保存模型的隐藏思维链，只保存简短、可展示的结论依据；
- AI 不输出仓位、订单数量，也不调用交易接口。

### 6.3 AI 分数与否决规则

当 `decision=SELECT` 时：

```text
A = 60% × suitability_score + 40% × confidence × 100
```

当 `decision=REJECT` 或 `INSUFFICIENT_DATA` 时，`A=0` 且直接淘汰。以下情况也直接淘汰：

- `risk_level=HIGH`；
- AI 指出关键数据冲突且冲突无法由确定性校验消除；
- JSON 校验失败并在一次受控重试后仍失败；
- 模型、提示词或数据输入与运行冻结版本不一致。

第 5.8 节冻结的 AI 候选清单就是本次运行的“计划 AI 调用集合”。其中任何一只在受控重试后仍无有效响应，本次运行即为 `partial`；有效的 `REJECT` 或 `INSUFFICIENT_DATA` 属于已完成响应，不算调用失败。AI 服务整体不可用时，页面可以展示“待 AI 确认”的量化 Top 30 便于诊断，但最终榜单为空；禁止沿用旧 AI 结论或把纯量化结果标成最终入选。

### 6.4 模型职责与升级门禁

首版推荐 `deepseek-v4-flash`。它只处理量化 Top 30 的新闻/事件风险核对、持有期适合度判断、`SELECT/REJECT` 决策和排序所需 A 分；不负责识别产品类别、生成硬过滤结果、计算 Q，且不能推翻 H1～H8。模型别名必须在运行开始时解析并记录供应商返回的不可变模型 ID，避免别名静默升级后无法回放。

目前不要求直接升级到 `deepseek-v4-pro`。是否升级应使用相同冻结输入，对 Flash 与 Pro 做影子评估，并同时满足以下条件后再发布新的模型策略版本：结构化输出有效率不下降，计划调用完成率满足 `≥95%` 的运营目标，按第 9.2 节计算的配对组合收益或预先定义的盲评质量有实质改善，且 P95 延迟与单次运行成本仍在产品预算内。Pro 只因参数规模更大或个别案例解释更长，不构成升级依据。

## 7. 数据与服务设计

### 7.1 数据来源优先级

| 数据 | 首选来源 | 说明 |
| --- | --- | --- |
| 美国证券目录 | 现有 Longbridge 官方证券目录快照 | `usmain` 作为统一点时召回范围；保存来源、版本、捕获时间和载荷哈希 |
| 交易状态 | Longbridge quote/static info | 复用现有 tradeability 能力并保存点时快照 |
| 日 K | Longbridge 日 K 或经验证的历史行情源 | 同一运行分别冻结前复权 OHLC 与未复权量价，禁止覆盖写入共享 `ohlc` |
| 行情基础指标 | Longbridge calc indexes | 复用现有批量指标能力，不使用股票市值/ETF 规模作统一门槛 |
| 市场基准 | SPY 日 K | 仅用于 RS20/RS60 |
| 新闻 | 现有 Tavily 新闻链路 | 保存去重后的点时快照 |
| 财报及公司行动 | 现有 FundamentalContext | 缺失状态必须显式传给 AI |
| AI | 当前推荐的 `deepseek-v4-flash` | 记录请求别名和供应商不可变模型 ID；模型策略版本进入缓存键 |

Longbridge 接口负责提供可复算的基础事实，本地后台任务负责在运行开始时将目录、交易状态、交易日历、前复权 K 线和未复权量价冻结为版本化点时数据包。版本化数据包是回放与缓存所需的本地治理能力，不是新的外部数据供应商。目录内证券即使产品类别未知也可继续；名称正则和 AI 推测不得把未知类别包装成已验证事实。

Longbridge 官方文档验证后的调用契约如下：

| 能力 | 官方接口与限制 | 本功能用法 |
| --- | --- | --- |
| 静态信息 | [`static_info`](https://open.longbridge.com/docs/quote/pull/static)；单次最多 500 个代码，返回 `board`、`exchange` 等 | 500 只一批，确认 `USMain` 与交易所；`NASD` 标准化为 NASDAQ，不读取或推测产品类别 |
| 当前报价 | [`quote`](https://open.longbridge.com/docs/quote/pull/quote)；单次最多 500 个代码，支持所有证券类型 | 500 只一批，只取交易状态与最近价；必须以 `include_depth=false` 调用，不获取盘口 |
| 交易日历 | [`trading_days`](https://open.longbridge.com/docs/quote/pull/trade-day)；查询区间不超过一个月且只支持最近一年 | 确定最近已完整结束的美国交易日，并使用 `half_trading_days` 识别 13:00 ET 提前收市 |
| 历史 K 线 | [`history_candlesticks_by_date`](https://open.longbridge.com/docs/quote/pull/history-candlestick)；单标的请求，单次最多 1000 根；账户每月可访问的唯一标的总量按等级为 100～3000 | 每只候选分别请求 `ForwardAdjust` 与 `NoAdjust`，同一运行独立冻结；不写入缺少 `adjust_type` 维度的共享 `ohlc` |

因此，“Longbridge 能直接返回所需字段”和“当前账户能在一次冷运行中完整覆盖全部 `usmain`”是两个不同结论。前者成立，产品元数据供应商与 NBBO 供应商均可删除；后者必须在生产启用前以当前账户行情等级、当月剩余额度、H1～H4 后实际唯一标的数和冷运行耗时验证。官方文档只给出等级区间，不能假设所有账户均有 3000 只额度，也不能假设 3000 足以覆盖当日全集。

当前实现的完整性规则固定如下：

- 未配置 `QUANT_SELECTOR_BUNDLE_PATH` 时，运行实时调用 Longbridge 自动采集，并要求按账户在 Longbridge “My Quotes” 中显示的月度唯一标的额度配置 `QUANT_SELECTOR_HISTORY_SYMBOL_LIMIT`（1～3000）；配置数据包路径时只用于冻结数据包回放和可重复测试；
- 静态信息和报价按 500 只分批，历史 K 线按单标的请求；任何供应商异常保存到 `source_capture.errors` 并使运行成为 `partial`；
- 历史采集前先用目录、交易所、交易状态和最近价完成 H1～H4 预过滤，只对仍可继续的标的和 SPY 请求 K 线；所需数量超过配置额度时在第一条历史请求发出前失败关闭；
- 供应商明确成功返回某证券无足够历史时，该证券按 H6 排除，不把整个运行标为 `partial`；
- 如果完整候选所需的唯一标的数超过账户可用历史行情额度，不得截断后把剩余集合称为“全市场完整运行”。生产方案只能选择提升 Longbridge 行情等级、接入经验证且可点时回放的全市场历史行情源，或另立规则版本定义可审计的粗筛候选集；第三种方案会改变召回率和结果含义，不能作为 v1.3 的静默降级。

### 7.2 后端模块

建议新增独立模块，复用底层数据加载器，不复用 LONG/SHORT 池数据模型：

```text
backend/app/quant_stock_selector.py
backend/app/quant_stock_selector_ai.py
backend/app/routers/quant_stock_selector.py
backend/tests/test_quant_stock_selector.py
backend/tests/test_quant_stock_selector_ai.py
```

服务职责：

- `UniverseService`：从点时 `usmain` 目录生成统一候选全集并执行 H1～H8；
- `MarketSnapshotService`：分别冻结前复权 OHLC 和未复权量价，生成内容哈希并提供不可变引用；
- `QuantScoreService`：按冻结版本计算 Q 和分项；
- `AISelectionService`：只处理量化 Top 30，验证结构化输出并计算 A；
- `QuantSelectionService`：编排运行、计算 F、统一排名、持久化和 SSE 进度；
- 现有外部服务超时、重试、限流、熔断和错误脱敏逻辑继续复用。

### 7.3 API

```text
POST /api/quant-stock-selector/runs
GET  /api/quant-stock-selector/runs/{run_id}
GET  /api/quant-stock-selector/runs/{run_id}/events
GET  /api/quant-stock-selector/runs/{run_id}/results
GET  /api/quant-stock-selector/runs?limit=20
GET  /api/quant-stock-selector/latest
```

`POST /runs` 首版不接收市场、方向、因子权重或阈值，只允许可控的 `force_refresh=false`。这样可以保证同一版本结果可比较，也避免新页面重新变成参数面板。

每次 `POST /runs` 都生成新的唯一 `run_id`。`force_refresh=false` 表示完成本次输入捕获和哈希计算后可以查询缓存；命中时新运行通过 `reused_from_run_id` 引用既有不可变结果，不复用其运行身份。`force_refresh=true` 只跳过缓存查询，仍必须保存新捕获的快照、全部哈希和最终缓存键；两次输入完全相同时允许得到相同内容哈希。

运行状态：

```text
queued → loading_universe → scoring_quant → analyzing_ai
       → completed | partial | failed | cancelled
```

状态语义固定如下：

- `completed`：所有必需输入快照均有效，AI Top 30 已按稳定排序确定，且计划 AI 调用集合中的每只标的均取得符合契约的响应；有效 `REJECT`/`INSUFFICIENT_DATA` 计为完成，零只候选或零只最终入选均可为 `completed`；
- `partial`：任一必需输入因超时、限流或供应商错误未能冻结，或任一计划 AI 调用失败；29/30 个 AI 响应也必须是 `partial`，诊断结果不得作为完整最终榜单发布；
- `failed`：全局错误导致连可用的量化运行都无法形成，例如候选目录或基准数据整体不可用；
- `cancelled`：用户或系统明确取消，已保存快照仍保留审计用途。

数据源成功返回“该标的没有满足 H6 的足够历史”属于可解释的硬过滤失败，不等同于捕获基础设施失败。只有完全 `completed` 的运行可以成为 `/latest` 的主结果和效果评估样本。

### 7.4 不可变快照与持久化

现有共享 `ohlc` 主键不含 `adjust_type`，不能同时表达前复权和未复权序列，历史读取也不能据此证明所返回的复权口径。因此本功能不直接复用 `ohlc` 作为可回放事实源，建议新增以下内容寻址表：

| 表 | 关键内容 |
| --- | --- |
| `quant_selection_runs` | 唯一 `run_id`、状态、`data_as_of`、规则/模型版本、阶段数量、错误摘要、`quant_input_hash`、`run_input_hash`、缓存键和 `reused_from_run_id` |
| `quant_selection_candidates` | 候选代码、所有硬过滤状态及排除原因、不可变输入引用、`candidate_quant_input_hash`、Q/A/F、分项、排名和是否最终入选 |
| `quant_selection_input_snapshots` | 证券目录、交易状态、SPY、新闻和事件等规范化原始载荷或不可变对象存储引用，包含来源、捕获时间、数据时点和载荷 SHA-256 |
| `market_bar_snapshots` | `snapshot_id`、代码、周期、`adjust_type`、来源、`captured_at`、`data_as_of`、`payload_hash`；内容一经写入不得更新 |
| `market_bar_snapshot_rows` | 以 `snapshot_id + timestamp` 为键的 OHLC、volume、turnover 行；数值口径继承父快照 |
| `quant_selection_ai_snapshots` | 每只计划候选的规范化 AI 输入、原始输出、解析输出、请求状态、`ai_input_hash`、模型和提示词版本 |

每次运行同时引用前复权 OHLC 快照和未复权量价快照；两个快照不得共用含义不明的行，也不得把一种复权请求覆盖写成另一种。所有候选都必须保存原始输入或上述不可变快照引用，包括硬过滤失败、上界剪枝和未进入 AI Top 30 的标的，不能只保存 AI Top 30。

### 7.5 输入哈希与缓存身份

哈希对象使用 UTF-8 编码的 RFC 8785 JSON Canonicalization Scheme 后计算 SHA-256。输入不得包含 `NaN`/`Infinity`；时间统一为 UTC RFC 3339 字符串；证券代码先标准化；K 线等有语义顺序的数组按交易时间升序，其余集合先按文档指定的稳定键排序。不可变引用进入哈希时使用其载荷 SHA-256、数据模式和来源版本，不使用随机数据库 ID 或可变存储 URI。哈希计算使用未舍入原始数值，数据库展示精度不参与哈希。

哈希分三层：

1. 每个候选计算 `candidate_quant_input_hash`；运行级 `quant_input_hash` 覆盖 `data_as_of`、SPY、候选全集的规范化量化输入或不可变引用、数据源/模式版本及完整硬过滤和排序前输入；
2. 对第 5.8 节每只计划候选的完整规范化 AI 请求计算 `ai_input_hash`，新闻、事件、目录证据及缺失状态都是输入的一部分；
3. `run_input_hash` 是根清单哈希，覆盖 `quant_input_hash`、第 5.8 节完整候选选择清单的哈希，以及按稳定顺序排列的 `{symbol, ai_input_hash}` 列表；无 AI 候选时列表为空但仍参与哈希。

缓存键为以下对象的 SHA-256，不再只依赖截止日和版本号：

```text
{
  run_input_hash,
  universe_version,
  filter_version,
  score_version,
  prompt_version,
  model_policy_version,
  resolved_model_id
}
```

只有状态为 `completed` 且所有快照仍可读取、哈希复验一致的运行可以命中缓存。`partial`、`failed`、`cancelled` 运行以及只有相同日期但输入不同的运行均不得复用。

## 8. 失败与降级

| 场景 | 行为 |
| --- | --- |
| 单只产品资产类别、ETF 方向或杠杆未知 | 不影响候选资格和运行状态；不允许 AI 将推测结果写成已验证事实 |
| `usmain` 目录整体不可用或目录快照无法冻结 | 无法形成候选全集，运行标记为 `failed` |
| 数据源成功返回单只标的 K 线不足 | 相关标的按 H6 排除，不给中性分；保存原始响应或不可变引用 |
| SPY 基准不可用，或供应商错误导致必需快照无法冻结 | 无法形成量化运行则 `failed`；已有可用量化诊断但完整性不足则 `partial` |
| 新闻不可用 | AI 输入明确标记；禁止 AI 声称已验证新闻，AI 分最高限制为 75 |
| 适用的财报/公司行动数据不可用 | AI 输入明确标记；结果显示事件风险未知；`not_applicable` 不按缺失处理 |
| 单只 AI 调用失败 | 受控重试一次；仍失败则该标的为“AI 未完成”，不能入选，整个运行状态为 `partial` |
| AI 全局不可用 | 保留量化候选用于诊断，最终榜单为空，运行状态 `partial` |
| SSE 中断 | 通过运行快照恢复；进程 runtime 变化时终止旧运行，不伪造恢复 |
| 最终无合格标的 | 若所有必需输入和计划 AI 调用均完整，显示“本次无标的同时通过量化与 AI 门槛”，状态仍可为 `completed` |

禁止使用“数据缺失给 50 分”或“AI 失败沿用量化结论”的静默降级，因为这会改变排名含义并违反 AI 必须直接参与的需求。

## 9. 评估与监控

### 9.1 运行质量指标

- `usmain` 目录证据覆盖率：全部初始候选必须为 `100%`；不统计产品类别、ETF 方向或杠杆覆盖率；
- 硬过滤原因覆盖率：`100%`，不得出现无原因丢弃；
- AI 完成率：跨运行运营 SLO 为 `≥95%`；单次运行只要低于 `100%` 就标记 `partial`，95% 不是完整性阈值；
- AI 候选稳定排序可复算率：完整运行必须为 `100%`；
- 输入哈希有效率：`100%`；
- 相同不可变输入和版本重跑的 Q 分与排序一致率：`100%`；同一截止日但输入哈希不同的运行不得纳入一致率比较；
- 已冻结数据包或完整本地历史缓存上的评分与 AI 阶段目标时长：P95 小于 5 分钟；Longbridge 冷启动全量历史采集因单标的调用和账户额度不承诺该 SLO，必须单独记录 `source_capture` 耗时、请求数、唯一标的数、限流和错误率，完成容量测试后再制定冷采集 SLO。

### 9.2 选股效果评估

只使用状态为 `completed` 的运行，并按运行日构造以下三个同日起止的组合：

1. 最终分 Top 10；
2. 同一运行的纯量化 Q Top 10；
3. SPY 基准。

最终组合和纯量化组合均固定为 10 个槽位，每槽权重 10%；不足 10 只的空槽持有现金，收益记 0。纯量化组合严格取同一运行 H1～H8 通过且 `Q ≥ 65` 的前 10 只，不受 AI 决策影响。SPY 组合为 100% SPY。三个组合均在运行日之后的下一个 NYSE 交易日官方常规时段开盘价入场，并分别在第 5、10、20 个未来 NYSE 交易日的官方常规时段收盘价退出；不能用盘前、盘后或“最近价”代替。

收益使用经验证的总回报口径处理拆股和现金分红。退市标的使用权威退市现金结算价或最后可交易总回报价；若分红、退市或价格数据不足以确认收益，该标的标签为不完整，且对应运行日/持有期的组合标签也为不完整，不得按 0 收益填充。每个已填充槽位扣除买入 10 bps 和卖出 10 bps；现金槽不扣费，SPY 基准按同样的买卖成本扣费。

统计单位是“每个运行日的一笔组合收益”，不是单只证券观测。每个持有期分别计算同一运行日的 `最终组合 - 纯量化组合` 和 `最终组合 - SPY` 配对差值，以处理候选数不同；不得把 300 只重叠证券标签视为 300 个独立样本。

首轮效果报告至少满足：

```text
不同的完整运行日 ≥ 60
每个持有期有效配对运行日 ≥ 40
跨运行 AI 完成率 SLO ≥ 95%
目录证据与输入哈希覆盖率 = 100%
交易成本代理 = 买入 10 bps + 卖出 10 bps
```

报告展示平均/中位组合收益、对 SPY 超额收益、胜率、组合净值最大回撤、Top 10 换手率，以及“最终榜单相对纯量化榜单”的配对收益差。对按日期排序的配对差值采用日期聚类的 circular moving-block Bootstrap：2,000 次重采样、95% 区间、固定随机种子 `20260725`，默认块长为 `max(2, ceil(有效不同日期数^(1/3)))`；整块抽取运行日以保留 5/10/20 日标签重叠和序列相关性，可复用现有 `stock_picker_ai_evaluation.py` 的移动块实现。

只有“最终组合减纯量化组合”的配对 Bootstrap 95% 区间下界不低于 0，才可以描述为“当前样本中 AI 重排有正向增量”。门禁不足时只展示覆盖情况，不输出收益结论；任何跨模型比较必须按相同运行日、相同冻结输入和相同交易成本做配对。

## 10. 实施顺序

### 阶段 0：Longbridge 点时数据包

- 以 Longbridge `usmain` 作为统一召回范围，不再接入独立产品元数据源；
- 自动采集并冻结目录、交易状态、XNYS 交易日历、前复权 OHLC、未复权量价和 SPY 基准；
- 静态信息和报价按官方上限每批最多 500 只，历史 K 线按单标的分别请求前复权与未复权序列，全程不调用 `depth`；
- 上线前记录当前账户的历史行情月度唯一标的额度，并以 H1～H4 后的实际标的数执行容量门禁；额度或冷采集耗时不满足时，不得宣称阶段 0 已通过；
- 每类快照保存来源、捕获时间、数据时点、模式版本和载荷 SHA-256；
- 用正常交易日、提前收市日、目录变更、复权/未复权隔离和重放一致性样本完成验收；
- 产品类别、ETF 方向、杠杆倍数和 NBBO 均不是本阶段门禁。

### 阶段 1：量化流水线

- 实现前复权 OHLC 与未复权量价的独立不可变快照，不向共享 `ohlc` 混写复权类型；
- 实现 H1～H8、`quant-selector-score-v1.2` 精确 Q 算法及 `Q ≥ 65` 的稳定排序 Top 30；
- 保存候选全集、原始输入或不可变引用、排除原因、分项、哈希与版本；
- 用固定输入制作公式、缺失数据、阈值边界、并列排序和哈希确定性测试。

### 阶段 2：AI 最终确认

- 实现新提示词和 JSON Schema 校验；
- 实现 A、F、否决规则、逐候选 `ai_input_hash`、根清单哈希和失败策略；
- 对 Flash/Pro 使用相同冻结输入建立影子评估，但首版继续使用通过验收的 Flash；
- 验证任一计划 AI 调用失败时运行是 `partial`、完整最终榜单不发布，而量化诊断仍可读取。

### 阶段 3：独立菜单

- 在 `Sidebar.tsx`、`App.tsx` 和 `Layout` 的 Tab 类型中接入新页面；
- 实现单按钮工作流、SSE 恢复、榜单、详情抽屉和历史运行；
- 在桌面与移动视口验证表格、抽屉、长文本及错误状态无重叠和横向溢出。

### 阶段 4：样本积累与调参

- 默认只采集和评估，不自动下单；
- 达到第 9.2 节门禁后，按运行日配对组合和 circular moving-block Bootstrap 评估 AI 增量；
- 任何阈值或权重调整都通过新版本和并行回测完成，不覆盖 v1 历史。

## 11. 验收标准

- 侧边栏存在独立“量化优选”菜单，原“智能选股”行为不变；
- 页面没有市场和多空选择，后端首版不暴露市场或方向参数；
- `usmain` 目录中的所有证券使用相同公式、门槛和排名，不分组、不保留类型或方向配额；
- 产品类别、ETF 方向或杠杆未知不导致排除、`partial` 或 `failed`；OTC 和不合资格交易所标的有明确排除原因；
- SPY 必须以 H8 和 `benchmark_symbol` 原因排除，不能进入量化或最终榜单；
- Q、A、F 可按本文公式精确复算，权重总和均为 100%；
- AI 未给出有效 `SELECT` 时，任何标的都不能进入最终结果；
- 计划 AI 调用 29/30 完成时运行必须为 `partial`；AI 或关键数据失败时不静默回退为“已入选”；
- 相同快照与版本重复计算得到完全一致的量化分和排序；
- 同日目录、行情、新闻或事件任一实际选股输入不同时，`run_input_hash` 和缓存键必须不同；`force_refresh` 不跳过快照和哈希保存；
- 前复权 OHLC 与未复权量价可同时回放且不会覆盖；任何候选均可追溯到原始输入或不可变快照；
- 每个结果可追溯到 `usmain` 目录证据、行情截止日、量化输入哈希、AI 输入/输出和版本；
- 不配置产品元数据和 NBBO 供应商时仍能产生完整运行；AI Top 30 可由冻结 Q 分和稳定排序直接复算；
- Longbridge 静态信息和报价请求每批不超过 500 只，历史 K 线失败可追溯到具体标的并令运行 `partial`；账户额度不足时不得通过截断候选伪造完整运行；
- Top 10 在后端按统一分数产生，所有证券均无类型配额或单独排序；
- 新增后端专项测试、前端类型检查和生产构建全部通过。

## 12. 与现有智能选股的关系

现有实现已经具备官方 Screener、行情与基本面补充、统一量化评分、AI Top N、快照、任务恢复及评估基础。新功能应复用这些稳定的底层加载器和可靠性保护，但不能直接把现有 LONG 池页面换一个菜单名称：

- 现有评分 `stock-picker-v2.1` 偏重趋势、动量、支撑阻力、量价、K 线形态和波动，并支持双向机会；新评分服务美国主板统一证券筛选，更强调成交额流动性和相对 SPY 强度，所有产品按自身价格序列评分，不建立 SHORT 分支；
- 现有最终机会分为 70% 量化、20% AI 方向一致性、10% 趋势强度；新功能使用 70% 量化、30% AI，并要求 AI 明确 `SELECT`，职责不同；
- 现有 AI 失败可以回退到量化结论；新功能为了满足“AI 直接参与确定选股”，只能展示待确认量化候选，不能产生最终入选；
- 现有证券目录分类的 `listed_equity_board_including_funds` 直接作为首版召回边界；阶段 0 不再等待外部产品分类或 NBBO 数据源，但仍必须通过 Longbridge 历史行情额度和冷采集容量门禁。

以上边界确保新菜单足够简单，同时不会通过隐藏复用旧逻辑而破坏需求含义。
